# 核心工作流与回归门禁

## 建立基线

- 正确性：记录最小输入、预期结果、返回值、所有权状态和宏值。
- 性能：记录工作负载形态、输入尺寸/深度、编译配置、重复次数和测量来源；单次耗时不能宣称普遍收益。
- 内存：记录分配器、平台、payload 形态及测量的是节点、整树、峰值还是报告层内存。
- crash：保留最小复现、栈/日志证据与 sanitizer/QEMU 配置。

## 按影响选门禁

| 变更 | 最低证据 | 何时扩大 |
| --- | --- | --- |
| 局部确定性缺陷 | 定向 Unity runner | 改到共享辅助、公开行为或宏路径 |
| Parse、Print、分配或所有权路径 | 定向 unit + fuzz quick | 改到新输入类、回滚或 sanitizer 路径 |
| 布局、对齐、FreeRTOS 或 fault | unit + QEMU | 改到第三方或硬件配置 |
| 性能或内存优化 | 正确性回归 + 前后测量 | 测量进入 CI/报告或权衡影响默认值 |
| 宏默认值或语义 | 所有受影响 unit + 文档 | 改动 API 兼容性或 QEMU/fuzz 行为 |

## 交付内容

报告目标、基线、变更的不变量/路径、验证命令与结果、已测收益或无收益、兼容影响和回滚触发条件。不能把缺失证据写成确定结论。
