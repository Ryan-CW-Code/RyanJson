# RyanJson 工作流协调

把请求推进到具体结果，不能只报出下一个文档或 skill 名称。

## 阅读顺序

1. 阅读 [任务路由](../shared/routing.md)。
2. 涉及仓库、构建、脚本、CI 或报告时阅读 [仓库事实](../shared/repository-facts.md)。
3. 涉及代码语义、所有权或验证时阅读 [行为契约](../shared/behavior-contracts.md)。

## 工作步骤

1. 重述要交付的结果，识别会影响正确性、兼容性或验证的关键约束。
2. 用路由表选一个主所有者；跨领域时按表中顺序执行，并维护同一份任务上下文。
3. 从源码、测试、脚本和报告收集当前证据，分开已验证事实与推断。
4. 实施或协调实施。交接时带上原目标、证据、所有权判断与验证状态。
5. 先选最小充分验证；涉及共享行为、公开契约、硬件语义或 CI 时再扩大门禁。
6. 交付结果、变更文件、验证证据、剩余假设与可独立延后的工作。

## Specialist 交接

- 公开接入、API 选型或调用方所有权：进入 [API 使用](../ryanjson-api-usage/SKILL.md)。
- 内核实现、宏语义、性能、分配或 crash 诊断：进入 [核心工程](../ryanjson-core-engineering/SKILL.md)。
- 测试归属、重复覆盖、fuzz 回归或测试执行：进入 [测试工程](../ryanjson-test-engineering/SKILL.md)。

## 仓库与文档任务

- 先改权威源，再改生成产物；禁止手改生成 runner 列表或报告。
- 文档事实变动时，同一次更新其对应的权威 skill 文档；只有路由所有者变化时才修改路由表。

## 交付契约

- 有助理解时说明主所有者和跨领域顺序。
- 分开说明已验证事实、假设和待验证项。
- 代码变更必须说明行为、所有权和验证状态；纯导航只给最短有效下一步。
